# Гайд: как мы работаем через Rojo

Этот документ — инструкция для тебя. Я (нейросеть) работаю с файлами в git-репозитории,
ты забираешь их в Roblox Studio через Rojo. Rojo синхронизирует файлы **автоматически**:
я пушу правку → ты делаешь Pull → в Studio код обновился сам, ничего перетаскивать не надо.

---

## Часть 0. Что нам понадобится (ставится один раз)

| Инструмент | Зачем | Откуда |
|---|---|---|
| **Rojo CLI** | синхронизирует папки репозитория со Studio | github.com/rojo-rbx/rojo/releases |
| **Rojo Plugin** | кнопка "Connect" внутри Studio | тот же релиз, файл `rojo-plugin.rbxmx` |
| **GitHub Desktop** | качает репозиторий и обновляет его одной кнопкой | desktop.github.com |
| **Roblox Studio** | сама студия | roblox.com |

GitHub Desktop рекомендую именно потому, что он заменяет все команды git одной кнопкой.
Если git тебе привычен — можешь пользоваться им, команды я тоже напишу.

## Часть 1. Установка Rojo

### Шаг 1.1 — Скачать Rojo CLI

1. Открой https://github.com/rojo-rbx/rojo/releases
2. Возьми **последний** релиз (сверху)
3. В списке ассетов скачай файл под свою систему:
   - Windows → `rojo-X.Y.Z-win64.zip`
   - macOS → `rojo-X.Y.Z-macos.zip`
   - Linux → `rojo-X.Y.Z-linux.zip`
4. Распакуй архив в удобную папку, например `C:\rojo\`
5. Там будет лежать `rojo.exe` (или просто `rojo` на macOS/Linux)

**Проверить, что работает.** Открой терминал (Windows: `Win+R` → `cmd`) и выполни:

```
C:\rojo\rojo.exe --version
```

Должно напечатать что-то вроде `rojo 7.4.4`.

> 💡 Чтобы писать просто `rojo` вместо полного пути, добавь папку `C:\rojo` в PATH:
> Панель управления → Система → Дополнительные параметры → Переменные среды →
> в переменной `Path` добавить `C:\rojo`. После этого **перезапусти** терминал.
>
> Это необязательно — можно всегда запускать по полному пути.

### Шаг 1.2 — Установить плагин в Studio

1. В том же релизе скачай файл **`rojo-plugin.rbxmx`**
2. Открой Roblox Studio
3. Перетащи этот файл мышкой прямо в окно Studio
4. Studio спросит, куда положить — выбери **Plugins** (или просто подтверди установку)
5. Проверь: сверху в Studio появилась вкладка **Plugins**, а в ней кнопка **Rojo**

Если файла плагина в релизе не оказалось:
в Studio открой **Toolbox** → вкладка Plugins → поиск `Rojo` → установи от автора `rojo-rbx`.

### Шаг 1.3 — Установить GitHub Desktop

1. Скачай с https://desktop.github.com
2. Войди под своим аккаунтом GitHub
3. Готово

## Часть 2. Скачать репозиторий

### Через GitHub Desktop (проще)

1. Открой в браузере https://github.com/damirgadylsin75-bot/turbo-garbanzo
2. Нажми зелёную кнопку **Code** → **Open with GitHub Desktop**
3. Выбери папку на диске, например `C:\projects\` → **Clone**
4. Репозиторий появится в `C:\projects\turbo-garbanzo`

### Через git (если привычнее)

```bash
git clone https://github.com/damirgadylsin75-bot/turbo-garbanzo.git
cd turbo-garbanzo
git checkout arena/afbcf97a-turbo-garbanzo
```

⚠️ **Важно про ветку.** Рабочая ветка этой сессии: `arena/afbcf97a-turbo-garbanzo`. Переключись на неё в GitHub Desktop и получай правки через Pull origin. Не переключайся на main для тестирования.

Если репозиторий станет приватным — GitHub Desktop попросит авторизоваться,
это нормально, просто войди в аккаунт.

## Часть 3. Первый запуск

### Шаг 3.1 — Подготовить Studio

1. Открой Roblox Studio → **New** → **Baseplate**
2. Сохрани куда угодно, например `C:\projects\mma-test.rbxl`
   (сохранять можно вне папки репозитория — так чище)
3. **Обязательно поставь R15:**
   `File` → `Game Settings` → `Avatar` → **Player Character Type** → **R15**
   Без R15 хитбоксы не совпадут с костями и удары не будут регистрироваться.

### Шаг 3.2 — Запустить Rojo

Открой терминал **в папке репозитория** и выполни:

```bash
cd C:\projects\turbo-garbanzo
rojo serve
```

(или `C:\rojo\rojo.exe serve`, если PATH не настраивал)

Терминал напишет что-то вроде:

```
Rojo server listening on port 34872
```

**Оставь это окно открытым.** Пока оно работает — синхронизация идёт.
Закроешь терминал → связь пропадёт.

### Шаг 3.3 — Подключить Studio

1. В Studio открой вкладку **Plugins**
2. Нажми **Rojo**
3. В появившемся окне нажми **Connect**
4. Статус должен стать **Connected**

Готово. В окне **Explorer** появятся папки:

```
ReplicatedStorage
  ├── Shared        <- FrameData, StaminaSystem, Moves, ...
  └── FightData     <- moves.json, fighters.json
ServerScriptService
  └── Server        <- MatchServer, FighterState, HitboxSystem, ...
StarterPlayer
  └── StarterPlayerScripts
      └── Client    <- InputBuffer, AnimDriver, CameraRig, VFX, HUD
```

Если папки появились — всё работает, можно жать **Play**.

## Часть 4. Наш рабочий цикл

Вот как мы будем работать дальше. Это главное, ради чего ставился Rojo.

```
  ┌─────────────────────────────────────────────────────┐
  │ 1. Я пишу/правлю код и пушу в репозиторий            │
  │ 2. Ты жмёшь "Pull origin" в GitHub Desktop           │
  │ 3. Rojo САМ обновляет код в Studio  ← ничего делать  │
  │    не надо, перетаскивать файлы не надо              │
  │ 4. Ты жмёшь Play и тестируешь                        │
  │ 5. Если ошибка — копируешь текст из Output и шлёшь   │
  │    мне                                               │
  │ 6. Возврат к шагу 1                                  │
  └─────────────────────────────────────────────────────┘
```

**Шаг 2 в деталях:** в GitHub Desktop сверху есть кнопка **Pull origin**
(или `Current Branch` → `Pull`). Нажал → файлы на диске обновились →
Rojo подхватил их в Studio **автоматически**, перезапускать ничего не нужно.

Иногда Rojo нужно «пнуть»: если изменения не появились, нажми в окне плагина
Rojo кнопку **Reconnect**.

## Часть 5. Как правильно присылать мне ошибки

Это сильно ускоряет починку.

1. В Studio открой панель вывода: **View** → **Output**
2. Нажми Play и повтори действие, которое сломалось
3. В Output появится красный текст — **скопируй его целиком**, вместе со строками
   вида `Server.MatchServer:142` (это путь к файлу и номер строки)
4. Пришли мне:
   - сам текст ошибки (полностью, не «что-то про nil»)
   - что ты нажимал перед этим (например: «нажал R2, боец ударил, потом ошибка»)
   - если возможно — скриншот окна Output

Полезно также включить: `File` → `Game Settings` → ничего, а в Output нажать
правой кнопкой → **Show Timestamps** и снять галочку с **Filter** — так видно
предупреждения, а не только ошибки.

## Часть 6. Куда вставлять анимации

Одно место: **`src/client/AnimDriver.luau`**, таблица `ANIMATIONS`.

```
M.ANIMATIONS = {
    jab       = "rbxassetid://ТВОЙ_ID",
    cross     = "",        <- пусто = анимация не подключена
    ...
}
```

Правила:
- Анимация должна быть сделана для **R15**
- ID берётся из Animation Editor после **Publish to Roblox**
- Пока ID пустые — **игра всё равно работает**: логика считается по кадрам,
  просто удары невидимые. Можно вставлять анимации постепенно
- Анимации должны быть в твоём аккаунте или публичными, иначе Studio их не загрузит

Список нужных для тестовой версии: `jab`, `cross`, `hook_left`, `hook_right`,
`uppercut_right`, `overhand_right`, `kick_low`, `kick_body`, `kick_head`, `block`, `slip`, `duck`, `knockdown`, `getup`, `idle`.

## Часть 7. Если что-то не так

| Симптом | Причина | Решение |
|---|---|---|
| Кнопка **Connect** серая / нет вкладки Rojo | плагин не установился | повтори шаг 1.2, проверь что файл именно `.rbxmx` |
| Connect выдаёт ошибку подключения | `rojo serve` не запущен | запусти `rojo serve` в папке репозитория и оставь окно открытым |
| Подключилось, но папок нет в Explorer | не тот проект открыт | убедись что `rojo serve` запущен **в папке репозитория**, где лежит `default.project.json` |
| Код обновился на диске, но в Studio старый | Rojo потерял связь | в окне плагина нажми **Reconnect** |
| Порт занят (`address in use`) | другой процесс на 34872 | `rojo serve --port 34873` и в плагине укажи тот же порт |
| Удары не регистрируются | персонаж R6, а не R15 | Game Settings → Avatar → R15 (шаг 3.1) |
| Удары проходят сквозь соперника | хитбоксы не видны для проверки | в Command Bar выполни `workspace:SetAttribute("FightDebugHitboxes", true)` — хитбоксы станут полупрозрачными цветными кубами |
| Анимации не проигрываются | нет ID или анимация R6 | впиши ID в `AnimDriver.ANIMATIONS`, убедись что анимация R15 |
| Боец не двигается с геймпада | Roblox перехватывает кнопки | это я закрываю в коде; если осталось — пришли текст из Output |

**Command Bar** — это строка ввода внизу Studio: `View` → `Command Bar`.

## Часть 8. Чего я НЕ могу

Честно, чтобы не было ложных ожиданий:

- ❌ Я **не вижу твой экран** и не могу управлять Roblox Studio
- ❌ Я **не могу нажать Play** за тебя и посмотреть, что получилось
- ❌ Я **не вижу твои анимации** — только ID, которые ты впишешь
- ❌ Я не могу запускать Roblox-сервер у себя: код я проверяю офлайн-парсером
  (`tools/luau_syntax_check.py`), а не реальной игрой

Поэтому цикл всегда такой: **я пишу → ты запускаешь → ты присылаешь ошибки → я чиню.**
Твоя часть — это глаза и руки в Studio. Без текста ошибок из Output я работаю вслепую.

Что я **могу**: писать и править весь код, генерировать данные, проверять синтаксис
всех файлов до пуша, объяснять каждую строку, калибровать числа под твои замеры из UFC 4.
