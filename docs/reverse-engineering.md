# Как зареверсить «физику» UFC 4 (легально и практично)

## 0. Что можно, а что нельзя

| Действие | Статус |
|---|---|
| Смотреть геймплей, считать кадры, снимать тайминги, записывать свои таблицы | ✅ можно |
| Воссоздавать механику своей реализацией в Roblox | ✅ можно (идеи/механики авторским правом не защищены) |
| Копировать анимации, модели бойцов, звуки, логотипы, имена реальных бойцов из UFC 4 | ❌ нельзя (Roblox DMCA-бан) |
| Декомпилировать exe, читать память процесса, распаковывать ассеты EA | ❌ нельзя (нарушение EULA + юридические риски) |

Весь план ниже построен на **наблюдении за видео** — это «чёрный ящик»: ты меряешь входы и выходы, а не лезешь в код. Так делают балансировщики в любом файтинге.

---

## 1. Что именно реверсим: 7 систем

«Физика UFC 4» — это не физический движок. Это 7 отдельных систем:

1. **Фреймдата** — startup/active/recovery каждого приёма (в кадрах 60 fps).
2. **Хитбоксы/хуртбоксы** — где и когда появляется зона попадания, по каким частям тела.
3. **Стамина** — как тратится, как регенит, что происходит при нуле.
4. **Урон/здоровье** — сколько снимает удар, что проходит через блок, как считается нокдаун.
5. **Стаггер/хит-реакции** — на сколько кадров противник «зависает», хитстоп.
6. **Греппл** — граф позиций (clinch → guard → side → mount → back), контесты, тайминги защиты.
7. **Мувмент/позиционирование** — скорость шага, контроль октагона, инерция поворотов.

Каждая система даёт отдельную таблицу. Все таблицы в итоге превращаются в `data/moves.json` и конфиги модулей.

## 2. Инструменты (бесплатные)

- **Запись экрана**: OBS Studio (60 fps, фиксированный битрейт) илиShadowPlay.
- **Покадровый просмотр**: VLC (клавиша `E` — следующий кадр) или VirtualDub2.
- **Разметка**: обычная Google Таблица / CSV + скрипт `tools/calibrate.py`.
- **Трекинг движения (для нейросетевой автоматизации)**:
  - **MediaPipe Pose** или **MMPose / RTMPose** — 33/17 keypoints по кадрам, бесплатно, локально.
  - **OpenCV** — покадровое извлечение, стабилизация, трекинг маркеров.
- **Тренировочный режим UFC 4**: там есть метрики (урон по зонам, точность) — снимай их как «ground truth» для калибровки урона.

## 3. Методика замера фреймдаты (пошагово)

1. Запиши **тренировочный бой** с неподвижным соперником (idle dummy).
2. Для каждого приёма запиши 3–5 повторов.
3. В VLC по кадрам отметь:
   - `F0` — первый кадр нажатия/начала замаха (рука тронулась);
   - `F1` — первый кадр, когда конечность достигла цели (или хитбокс «включился» по визуальному контакту);
   - `F2` — последний кадр контакта;
   - `F3` — кадр возврата в стойку (idle).
4. Тогда: `startup = F1 - F0`, `active = F2 - F1 + 1`, `recovery = F3 - F2`.
5. Повтори 5 раз, возьми **медиану** (не среднее — выбросы от анимаций смешения).
6. Занеси в `data/moves.json`.

**Точность ±1 кадр** уже даёт ощущение «как в UFC 4». Игроки не отличают 12 кадров от 13, но отличают 12 от 20.

### Что мерить обязательно (это и есть «физика»)

| Параметр | Как замерить | Куда писать |
|---|---|---|
| Дальность удара | Стоп-кадр в момент контакта: расстояние между центрами бойцов (в «условных головах», потом перевести в студы: рост бойца ≈ 5 студов) | `hitbox.reach` |
| Размер зоны удара | Обведи кулак/голень на стоп-кадре, сравни с шириной торса | `hitbox.size` |
| Отбрасывание | Замерь, на сколько смещается соперник за 10 кадров после удара | `reaction.knockback` |
| Стаггер | Сколько кадров соперник «висит» в анимации попадания | `reaction.stunFrames` |
| Хитстоп | Замирание обоих бойцов в момент контакта (кадры) | `client/VFX.CONFIG.hitstopFrames` |
| Урон | Тренировочный режим: здоровье до/после N ударов | `damage.health` |
| Стоимость стамины | Полная стамина → сколько ударов до нуля | `stamina.cost` |
| Реген стамины | Секундомер: сколько секунд от 0 до 50% в покое/в движении | `StaminaSystem.regenPerSecond*` |
| Шанс нокдауна | N повторов одного удара по уставшему dummy, считаем падения | `reaction.knockdownChance` |

## 4. Греппл: рисуем граф, а не физику

Сними отдельные клипы на каждый перевод. Для каждого запиши:

- из какой позиции доступен (standing / clinch / guard / side / mount / back);
- сколько кадров занимает попытка;
- какое **окно защиты** у соперника (сколько кадров есть, чтобы нажать защиту) — обычно 20–30 кадров;
- куда приводит успех и куда — провал;
- сколько стамины жрёт провал.

Результат — ориентированный граф, который уже описан в `src/server/GrappleSystem.luau` (`M.POSITIONS`, `M.PAIRS`, `move.grapple.from/to`). Тебе остаётся только подставить свои `power` и тайминги.

**Ключевой инсайт UFC 4**: на земле почти нет «физики». Есть позиции + таймеры + контесты. Пытаться симулировать партер через RigidBody — главная ошибка самодельных проектов: получишь «желе» вместо борьбы.

## 5. Как нейросети ускоряют каждый шаг

| Задача | Чем | Как |
|---|---|---|
| Покадровая разметка таймингов | MediaPipe + LLM-скрипт | Прогоняешь клип → keypoints по кадрам → скрипт ищет пик скорости запястья/стопы = `F1`. LLM пишет/дебажит этот скрипт |
| Извлечение чисел из видео | Vision-модель (GPT-4o/Gemini/Claude) | Кидаешь 5 стоп-кадров: «определи фазу мува и оцени расстояние между бойцами в долях роста» |
| Генерация кода | LLM (Arena Agent Mode) | «Вот мой moves.json, напиши resolver попаданий с чип-уроном и окном отмены» |
| Балансировка чисел | LLM + симуляция | Прогоняешь 10 000 боёв headless, LLM анализирует винрейты и предлагает правки `damage.health` |
| Анимации | Move.ai / Rokoko Video / DeepMotion | Видео удара → 3D-скелет → ретаргет на R15. Юридически чище, чем копировать из игры |
| ИИ-соперник | RL (PPO) поверх твоего движка | Награда = урон − пропущенный урон − стамина. Агент учится держать дистанцию |
| Документация | LLM | Из твоих замеров собрать таблицу и описание |

### Мини-пайплайн «видео → фреймдата» (можно собрать за вечер)

```
clip.mp4
  -> ffmpeg: кадры в png (60fps)
  -> MediaPipe Pose: csv с координатами wrist/ankle по кадрам
  -> python: скорость ключевой точки, поиск пика
  -> пик = F1, порог скорости = границы startup/active
  -> json: дописываем в data/moves.json
```

LLM (в том числе я) пишет все 4 шага скрипта. Твоя задача — скормить клипы и проверить результат глазами на 5–10 мувах.

## 6. Порядок работы (не пропускай шаги)

1. **Неделя 1**: 8 базовых страйков (джеб, кросс, 2 хука, лоу-кик, боди-кик, хэд-кик, блок). Замерил тайминги → забил в JSON → в Studio бьёшь dummy и сравниваешь ощущение.
2. **Неделя 2**: стамина + урон + нокдаун. Теперь бой «тяжелеет» к 3-му раунду.
3. **Неделя 3**: греппл-граф + тейкдауны + 3 наземные позиции + граунд-энд-паунд.
4. **Неделя 4**: сабмишены, эскейпы, хитстоп, камера, звук, HUD.
5. **Дальше**: баланс через симуляцию, ИИ-соперник, ростер, режимы.

## 7. Частые ошибки

- ❌ Считать урон физикой Roblox (`Touched`, `BodyVelocity`) — получишь случайные попадания и читерство.
- ❌ Плавающий `dt` в боевой логике — комбо «плывут». Только фиксированный шаг (уже сделано в `MatchServer`).
- ❌ Авторитетный клиент — первый же эксплойтер сломает бой. Клиент шлёт только `moveId`.
- ❌ Полный ragdoll в стойке — боец должен быть «кинематичным», ragdoll только на нокдауне.
- ❌ Пытаться скопировать 100% сразу. Копируй **ощущение**: тайминги + хитстоп + камера дают 80% сходства.
- ❌ Брать ассеты из UFC 4. Только свои или сгенерированные.
