# Как «вайбкодить» этот проект с нейросетями

Цель: ты формулируешь **что** должно происходить (с числами из замеров), нейросеть пишет **как**. Чтобы это работало, проект специально разложен на маленькие изолируемые модули — их легко генерировать и тестировать по отдельности.

---

## 1. Контракт между тобой и нейросетью

Ты всегда даёшь модели три вещи:

1. **Контекст** — какой модуль, какие типы (`FrameData.MoveDef`, `FighterState`), какой у него контракт.
2. **Наблюдения** — реальные числа из UFC 4 (тайминги, урон, отбрасывание). Без них модель выдумает «среднюю температуру».
3. **Критерий приёмки** — как проверить: тест, сценарий в Studio, «джеб должен успевать прервать кросс на 13-м кадре».

Плохой промпт: «сделай физику как в UFC 4».
Хороший промпт: «в `src/server/MatchServer.luau` в `resolveCollisions` хитбокс живёт все активные кадры и попадает дважды. Сделай так, чтобы один мув попадал максимум один раз (флаг `hitConsumed`), и добавь тест».

---

## 2. Порядок сборки с ИИ (проверенный)

| Шаг | Что просишь у модели | Что проверяешь сам |
|---|---|---|
| 1 | Каркас модуля + типы + сигнатуры функций | Что типы совпадают с `FrameData` |
| 2 | Реализацию **одной** функции | Тестом в `tests/` |
| 3 | Табличные данные (`moves.json`) по твоим замерам | 5–10 значений глазами по видео |
| 4 | Интеграцию в `MatchServer` | В Studio: dummy получает урон ровно один раз за мув |
| 5 | Рефакторинг/оптимизацию | Что тесты зелёные |

Никогда не проси «сделай всю боевую систему» одним промптом — получишь несогласуемые типы.

## 3. Промпты-заготовки (копируй и подставляй свои числа)

### Фреймдата
```
Вот мои замеры по видео (60 fps):
- jab: F0=0, F1=7, F2=9, F3=19, урон 5.5, отбрасывание 3 studs
- cross: ...
Обнови data/moves.json: посчитай startup/active/recovery,
сохрани схему существующих записей, не трогай остальные мувы.
```

### Resolver попаданий
```
В src/shared/FrameData.luau есть resolveHit().
Наблюдение из UFC 4: удар в блок снимает ~8% здоровья, но 135% стамины;
при удержании блока >30 кадров стамина горит быстрее;
при стамине < 20% шанс нокдауна растёт линейно до +45%.
Проверь, что код это делает, и добавь недостающие ветки + тесты в tests/FrameData.spec.luau.
```

### Греппл
```
Граф позиций: standing -> clinch -> guard_top/side_top/mount_top/back_top.
Замеры: окно защиты от тейкдауна 0.42 сек, двойная нога жрёт 20 стамины,
шанс = offense*стамина против defense*стамина.
Допиши GrappleSystem.attempt/update так, чтобы провал тратил стамину атакующего
и оставлял позицию без изменения, а успех переводил в move.grapple.to.
```

### Нетокод
```
Клиент шлёт только {action, moveId, dir}. Сервер авторитетен.
Напиши реконсиляцию в src/client/Prediction.luau: при расхождении moveId
клиент принимает серверный и доигрывает анимацию с текущего moveFrame,
без визуального рывка.
```

### Автобаланс
```
Вот лог 500 headless-боёв (CSV): moveId, количество использований, урон, винрейт.
Найди мувы с винрейтом > 58% и > 40% и предложи правки damage.health /
stamina.cost / timing.recovery. Ответ дай как diff к data/moves.json
и объясни каждое изменение одним предложением.
```

## 4. Нейросети, которые реально нужны (по типам задач)

### A. Код и данные — LLM (Arena Agent Mode, Copilot, Claude, GPT)
Пишут Luau, генерят `moves.json`, рефакторят, пишут тесты. 90% работы здесь.

### B. Видео → тайминги — pose estimation
- **MediaPipe Pose** (локально, бесплатно, Python) — 33 keypoints.
- **MMPose / RTMPose** — точнее, тяжелее.
- **Vision-LLM** (GPT-4o, Gemini, Claude) — «что происходит на этих 6 кадрах, оцени дистанцию».

Пайплайн: `ffmpeg` → png-кадры → pose csv → python-скрипт ищет пик скорости конечности → `F1` → дописываешь в JSON.

### C. Видео → анимации — motion capture
- **Move.ai**, **Rokoko Video**, **DeepMotion**, **Plask** — из обычного видео дают FBX/BVH.
- Ретаргет на R15: Blender (скелет Roblox R15) → FBX → Roblox Animation Editor → `Publish to Roblox` → assetId в `AnimDriver.ANIMATIONS`.

⚠️ Не бери анимации из самой UFC 4 — это прямой путь к DMCA.

### D. Сидентификация параметров (там, где «физика» настоящая)
Для нокдауна/отбрасывания снимается траектория и подбираются `k` (жёсткость) и `c` (демпфер) в `FightMath.springDamp`. Варианты:
- вручную: 3–4 итерации по видео;
- автоматически: `scipy.optimize.curve_fit` под снятую кривую смещения;
- LLM-агент, который гоняет симуляцию и минимизирует ошибку к видео.

### E. ИИ-соперник — reinforcement learning (позже)
`BotController` уже шлёт те же намерения, что игрок. Замена на RL-агента:
- состояние: дистанция, своя фаза, фаза соперника, стамина обоих, здоровье;
- действие: `moveId` из списка;
- награда: нанесённый урон − пропущенный − потраченная стамина + бонус за нокдаун;
- обучение: PPO в headless-симуляции (тот же `MatchServer`, только без Roblox-обвязки — `FrameData` и `StaminaSystem` специально чистые функции, их можно гонять в Python через `lupa` или переписать 1:1).

### F. Автобаланс — симуляция + LLM (уже работает)
```bash
python3 tools/simulate.py --fights 5000 --seed 42
python3 tools/simulate.py --report
```
1. Симулятор гоняет бои «бот vs бот» (4 архетипа: aggressive / counter / kicker / grappler)
   на тех же формулах, что и Luau: `resolveHit`, стамина, окна отмены, прерывание замаха.
2. На выходе `build/sim/moves_stats.csv`, `fights.csv` и `report.txt` с флагами
   («пере-урон на использование», «слишком точный», «низкое использование», «слишком часто роняет»).
3. Скармливаешь `moves_stats.csv` нейросети с промптом «Автобаланс» (раздел 3) →
   получаешь diff к `data/moves.json` → прогоняешь снова → сходишься за 3–5 итераций.

Что уже видно на стартовых числах (и что надо править замерами из UFC 4):
`kick_head` и `spinning_back_kick` пере-точны и пере-уронны, `jab` используется
редко — значит `damage.health` джеба и `knockdownChance` киков надо калибровать по видео.

⚠️ Формулы в `tools/simulate.py` обязаны совпадать с `src/shared/FrameData.luau`
и `src/shared/StaminaSystem.luau`. Изменил одно — измени другое.

## 5. Workflow в этом репозитории

```bash
# установить rojo (один раз)
npm i -g rojo   # или foreman / cargo install rojo

# смотреть проект в Studio
rojo serve      # -> в Studio включить Rojo-плагин и Connect

# собрать .rbxlx
rojo build -o turbo-garbanzo.rbxlx

# проверить данные (локально, без Studio)
python3 tools/calibrate.py --check data/moves.json
```

Тесты: в Studio вставь **TestEZ** в `ReplicatedStorage` и запусти
`tests/RunTests.server.luau` — он прогонит `tests/FrameData.spec.luau`.

## 6. Чек-лист «похоже на UFC 4»

- [ ] Джеб выходит быстрее кросса, кросс больнее
- [ ] Удар в блок почти не снимает здоровье, но сжигает стамину
- [ ] На нулевой стамине боец медленный и падает от хэд-кика
- [ ] Есть хитстоп (2–6 кадров замирания) при сильном попадании
- [ ] Окно наказания: промахнувшийся кросс наказывается джебом
- [ ] Тейкдаун защищается в окне ~0.4 сек
- [ ] На земле есть позиции, а не физическое «желе»
- [ ] Камера держит обоих бойцов и трясётся на нокауте
- [ ] Комбо работают через буфер ввода (нажал заранее — исполнилось в окне отмены)
